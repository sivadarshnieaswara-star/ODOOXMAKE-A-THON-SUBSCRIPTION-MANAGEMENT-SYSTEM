# Plan 02-02: Subscription Lifecycle State Machine & Policy Enforcement

## Goal
Implement the core Subscription data entity, subscription line calculations, sequential ID generator (`SUB-XXXXX`), state transition engine with strict policy enforcement, and RBAC-scoped subscription queries.

## State Machine Transition Specification
```
                 ┌───────────┐
                 │   Draft   │
                 └─────┬─────┘
                       │ submit_quote
                       ▼
                 ┌───────────┐
      ┌──────────┤ Quotation ├──────────┐
      │          └─────┬─────┘          │
      │ reject         │ confirm        │ cancel
      ▼                ▼                ▼
┌───────────┐    ┌───────────┐    ┌───────────┐
│  Closed   │◄───┤ Confirmed │    │  Closed   │
└───────────┘    └─────┬─────┘    └───────────┘
                       │ activate
                       ▼
                 ┌───────────┐
            ┌───►│  Active   │◄───┐
            │    └──┬──────┬─┘    │
            │       │      │      │
     resume │       │      │      │ pause
            │       │      │      │
            │       │      ▼      │
            │       │    ┌────────┴──┐
            │       │    │  Paused   │
            │       │    └───────────┘
            │       ▼ close
            │    ┌───────────┐
            └───-┤  Closed   │ (Renewal if allow_renewal=True)
                 └───────────┘
```

## Tasks

### Task 1: Subscription Service & State Transition Logic
- **Files**: `backend/app/services/subscription_service.py`
- **Action**:
  - Implement `generate_subscription_number(db)` producing sequential identifiers formatted as `SUB-{count:05d}`.
  - Implement `transition_status(db, subscription, target_status, user_role)`:
    - Validate allowable state transitions against the state graph.
    - Check plan policy constraints:
      - `target == PAUSED`: verify `plan.allow_pause`.
      - `target == CLOSED` while prior was `ACTIVE`: if `today < expiry_date`, verify `plan.allow_early_close`.
      - Renewal (`target == DRAFT/QUOTATION` from `CLOSED`): verify `plan.allow_renewal`.
- **Verify**:
  ```bash
  uv run python -c "from backend.app.services.subscription_service import SubscriptionService; print('SUBSCRIPTION_SERVICE_OK')"
  ```

### Task 2: Subscription Router & RBAC Permissions
- **Files**: `backend/app/routers/subscription_router.py`, `backend/app/main.py`
- **Endpoints**:
  - `GET /api/subscriptions`: Filterable by status, plan, customer. Customers see only their own subscriptions; Staff/Admin see all.
  - `POST /api/subscriptions`: Create subscription from lines or template (`require_staff_or_admin`).
  - `GET /api/subscriptions/{id}`: Detailed view with line items, current stage, and policy permissions.
  - `POST /api/subscriptions/{id}/transition`: Trigger lifecycle transition (`draft`, `quotation`, `confirmed`, `active`, `paused`, `closed`).
  - `POST /api/subscriptions/{id}/pause`: Dedicated action for portal customers and staff (checks `allow_pause`).
  - `POST /api/subscriptions/{id}/resume`: Resume paused subscription.
  - `POST /api/subscriptions/{id}/close`: Early termination or manual closure (checks `allow_early_close`).
- **Verify**:
  ```bash
  uv run python -c "from backend.app.routers.subscription_router import router; print('SUBSCRIPTION_ROUTER_OK')"
  ```
